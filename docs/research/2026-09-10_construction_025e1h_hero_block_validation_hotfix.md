## 2. Root cause

`docs/demo-assets/yamada-live-demo/scripts/integrate-025b2-hero-and-cases.php`（Construction 025-B2）の関数 `rebuild_cover_inner_html()` が、Hero Cover の保存markupを手組みする際に3点の誤りを犯していた:

1. **`wp-image-{id}` クラスの欠落**: `<img>` に `wp-block-cover__image-background` のみを付与し、WordPressのCover `save()` が必ず付ける `wp-image-{attachment_id}` を付けていなかった（関数内に `$attach_id` 相当の変数がスコープに無かった）。
2. **オーバーレイ用クラスを `<img>` に誤付与**: `has-contrast-background-color has-background-dim has-background-dim-20` を `<img>` へ付けていた。WordPress標準ではこれらは `<span class="wp-block-cover__background">` 側のクラス。
3. **`<span class="wp-block-cover__background">` 自体の欠落**: オーバーレイを描画する `<span>` 要素を出力していなかった。

`core/cover` は静的ブロック（`save()` がHTMLを生成、`render_callback` なし）なので、保存markupがGutenbergの `save()` 出力と1トークンでも食い違うと、Block Editorを開くたびに検証失敗 → 「invalid content」表示になる。

## 3. Expected WordPress markup

WP 7.1 バンドルのGutenberg `core/cover` `save()` が生成する正しい形（Block Editorの検証ログ「Content generated by `save` function」より、推測ではなく実機生成markupから確定）:

```html
<div class="wp-block-cover astrea-hero-photoplane" style="min-height:62vh">
  <img class="wp-block-cover__image-background wp-image-42" alt="" src="{url}" data-object-fit="cover"/>
  <span aria-hidden="true" class="wp-block-cover__background has-contrast-background-color has-background-dim-20 has-background-dim"></span>
  <div class="wp-block-cover__inner-container"></div>
</div>
```

要点:
- `<img>` のクラスは **`wp-block-cover__image-background wp-image-{id}` の2つだけ**。
- 色・濃度クラスは **`<span class="wp-block-cover__background">` 側**。
- 濃度クラスの順序は **`has-background-dim-{N}` → `has-background-dim`**（具体値が先、汎用が後）。
- `style` に末尾セミコロンなし（`style="min-height:62vh"`）。
- 要素順は `<img>` → `<span>` → `<div class="wp-block-cover__inner-container">`。

## 4. Actual previous markup

```html
<div class="wp-block-cover astrea-hero-photoplane" style="min-height:62vh">
  <img class="wp-block-cover__image-background has-contrast-background-color has-background-dim has-background-dim-20" alt="" src="{url}" data-object-fit="cover" />
  <div class="wp-block-cover__inner-container"></div>
</div>
```

`<span>` が丸ごと無い。`<img>` に本来 `<span>` に付くべきクラスが付いており、`wp-image-42` が無い。フロントエンド実測でも、この broken markup は `<img>` の `opacity` が `1`（濃度クラスは `<img>` には効かない）で、オーバーレイ用 `<span>` も無いため、**Hero写真がフル輝度・navyオーバーレイなしで表示されていた**。

## 5. Fix method

`rebuild_cover_inner_html()` を書き直し（`integrate-025b2-hero-and-cases.php`、025-E1H）:

- `$attach_id = isset( $attrs['id'] ) ? (int) $attrs['id'] : 0;` を読み、`<img>` クラスを `wp-block-cover__image-background` ＋（`$attach_id` があれば）` wp-image-{$attach_id}` のみに。
- 色・濃度クラスは新設した `$span_classes`（`wp-block-cover__background` ＋ `has-{overlayColor}-background-color` ＋ `has-background-dim-{dimRatio} has-background-dim`）へ。
- `<img>` → `<span aria-hidden="true" class="{$span_classes}">` → `<div class="wp-block-cover__inner-container">` の順で出力。
- `style` は `min-height` 値がある時のみ `min-height:{n}{unit}`（末尾セミコロンなし）。

**ブロックシリアライズ方式は変更なし**: 引き続き `parse_blocks()` → 属性更新（`url`/`id`/`dimRatio`）→ `rebuild_cover_inner_html()` → `serialize_blocks()` → `wp_update_post()`。手組みHTMLは属性由来で、WordPressの `save()` 出力と一致する形にした。検証抑制・JS非表示・エディタ限定hack・DB直編集・attachment IDハードコードは一切なし（Order §6の禁止事項すべて回避）。

docblockに、なぜこの形なのか（WPの `save()` 出力との一致要件）と、旧版の3つの誤りを明記。
